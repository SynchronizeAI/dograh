Dograh platform supports OpenAI, Anthropic, Google AI Studio, Google Vertex AI, Azure OpenAI, AWS Bedrock, Groq, Hopper, OpenRouter, Hugging Face, MiniMax, Sarvam, and Dograh-managed LLMs. There are some models provided by default for you to choose from the drop down.

<Warning>
LLM providers receive the data needed to generate responses, such as prompts, conversation history, model settings, and any configured tool/function definitions or tool call context. Review the provider's data processing, retention, model training, and regional hosting policies before using sensitive data.

For requests sent to the official OpenAI API endpoint, Dograh sets `store: false`. Custom OpenAI-compatible endpoints do not receive this field; their storage behavior follows the endpoint's policy.
</Warning>

For locally deployed or self-hosted LLMs, Dograh also supports OpenAI-compatible endpoints such as Ollama and vLLM.

## OpenAI reasoning effort

On an OpenAI connection, including an OpenAI-compatible endpoint, set `reasoning_effort` in the LLM settings when the selected model supports it. Leave it blank to use the model's default, except GPT-5 models, for which Dograh sends `minimal` reasoning effort and `low` verbosity by default.

A value you set overrides the GPT-5 reasoning effort while keeping low verbosity. Supported values depend on the selected model; check its API documentation before choosing one.

## Gemini prompt prefix caching

To opt in for a Gemini workflow, add exactly one standalone `<!-- cache-boundary -->` line to its composed system prompt. Dograh caches the non-empty, non-templated fixed text before the marker and the current tool schemas with Gemini for up to one hour. Keep caller-specific or changing instructions after the marker: Dograh removes the marker and sends the remaining prompt text as the first user message. Prompts with recording enabled bypass the cache. If the prefix is not eligible or cache creation or use fails, Dograh sends the request without a cache.

## OpenRouter provider routing

By default OpenRouter spreads requests across every provider that serves a model, weighted toward the cheapest. For voice agents that can add noticeable latency, because each turn may land on a slower provider.

Use **Provider order** to list the OpenRouter provider slugs to try first, in order, one slug per entry (for example, `groq`). The slugs are shown on each model's page on OpenRouter. If none of the listed providers is available, OpenRouter falls back to its other providers, so calls keep working.
