---
title: Speech recognition (STT) fallback
description: Optional backup recognizer when the primary speech-to-text provider fails during a call.
---

## Overview

`stt_fallback` accepts one rule with the `error` condition to select a backup recognizer.

On the first connection error the primary cannot recover from, the call switches to that recognizer and stays there until the call ends. An AssemblyAI session rejection also triggers a switch if Pipecat reports its `Error` message as `Unknown message type: Error`, before the websocket closes.

The switch does not replay audio the primary missed.

The policy is **off** when omitted or when `rules` is empty.

Without this policy, fallback handling leaves the configured recognizer and turn strategy unchanged.

It is ignored in **realtime** mode.

For pipeline calls, a **Dograh-managed** primary or target is rejected (the request fails with a 422), because Dograh manages its own fallbacks.

The backup must be a different provider than the primary, so a Deepgram outage does not take the backup with it.

## JSON shape

```json
{
  "stt_fallback": {
    "version": 1,
    "rules": [
      {
        "condition": { "type": "error" },
        "target": {
          "provider_connection_uuid": "<soniox-connection-uuid>",
          "settings": { "model": "stt-rt-v6", "language": "ko" }
        }
      }
    ]
  }
}
```

Set it on named model configurations, workflow overrides, and API-trigger overrides, next to `stt`.

Set the backup language to `en` or `ko` to match the call. If your workflows serve both languages, configure the matching backup language for each workflow. This example uses Soniox `stt-rt-v6` on a Soniox connection.

Resolved runs store the policy without credentials in the workflow snapshot.

## Behaviour

Pipecat's `ServiceSwitcher` routes audio to one recognizer at a time.

Its stock `ServiceSwitcherStrategyFailover` moves only after the service is no longer usable, which a websocket reaches after three reconnects spaced 4-10 seconds apart.

This policy stops those reconnects and connects the backup on the first connection error instead.

There is no health check and no switch back to the primary.

When a fallback replaces a primary that supplied external turn endings, later turns start from the backup transcript and local voice activity, then end through confidence-gated Smart Turn. A completion prediction must reach 0.99 confidence; lower-confidence predictions do not end the turn. Smart Turn uses the workflow's `smart_turn_stop_secs`, with a minimum of the 2-second default. The primary's provider-controlled turn endings stay active until failover occurs.

A named model configuration without a recognizer fallback never stores or returns the `stt_fallback` key.

An empty `rules` array disables an inherited policy.

An override that sets `mode` describes a whole configuration and does not inherit one.

See [Pre-Call Data Fetch](../voice-agent/pre-call-data-fetch) for which settings that hook can override.

Configure through the API today.

The Models UI editor does not yet offer this field.
