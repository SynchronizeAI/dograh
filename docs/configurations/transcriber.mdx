Dograh platform supports Deepgram, OpenAI, Google, Azure Speech, AssemblyAI, Speechmatics, Cartesia, Gladia, Soniox, Sarvam, Smallest AI, Hugging Face, ElevenLabs, and Dograh transcribers. You can take a look at the providers documentation of which language to select for your language requirements. 

<Warning>
Transcriber providers receive the data needed to transcribe speech, such as call audio, language settings, keyterms, and request metadata. Review the provider's data processing, retention, model training, and regional hosting policies before using sensitive data.
</Warning>

For locally deployed or self-hosted STT models, Dograh also supports Speaches, an OpenAI API-compatible server for streaming transcription.

Example: Deepgram has their language support documentation at https://developers.deepgram.com/docs/models-languages-overview#nova-3

## Deepgram Flux language hints

With the `flux-general-multi` model, **Language hints** biases transcription toward the languages you expect callers to speak. Pick several when callers switch between known languages, for example Hindi and English. Hints are combined with the **Language** setting, and leaving both on auto-detect lets Flux detect the language on its own.

Hints only help within the languages Flux multilingual supports. They do not add new ones. See [Deepgram's language prompting guide](https://developers.deepgram.com/docs/flux/language-prompting).

In **Dograh** mode, language hints are also available when you select auto-detect (`multi`) or a Flux-supported language. For bilingual English/Spanish calls, choose auto-detect and check **English** and **Spanish** under **Language hints**. These hints bias recognition toward both languages; they do not guarantee that other languages will be excluded.

Selecting a specific Flux-supported language combines that language with your hints. Hints are hidden and unused when you select a language that Dograh routes to its standard transcriber.

## AssemblyAI model and end of turn

AssemblyAI's default model is `u3-rt-pro`. To use Universal-3.7 Realtime
Agent, select `assemblyai-stt-3-7-realtime-agent`. Dograh lists Korean (`ko`)
for the 3.7 model; `u3-rt-pro` does not list Korean as a supported language.
See [AssemblyAI's model selection guide](https://www.assemblyai.com/docs/streaming/select-the-speech-model).

For cascade calls, select **AssemblyAI end of turn** in the workflow's turn
detection settings to use AssemblyAI's end-of-turn signal. It works with
AssemblyAI Universal-3 Pro models, including `u3-rt-pro` and the 3.7 Realtime
Agent. With another transcriber or an unsupported model, Dograh keeps the
selected transcriber's existing turn handling.

With AssemblyAI end of turn, you can set `max_turn_silence` (50 to 10000 ms) in
your STT model settings. It is the longest pause AssemblyAI waits before ending
a turn it is holding open, for example while a caller reads out a number.
Unset keeps AssemblyAI's default.

When a configured STT fallback takes over, turn handling changes for later
turns; see [Speech recognition (STT) fallback](./stt-fallback).

## Soniox end of turn

Turn on **Enable endpoint detection** in the Soniox STT settings to let Soniox
end the caller's turn instead of Dograh's local turn detection. It is off by
default. `max_endpoint_delay_ms` (500 to 3000 ms) is the longest silence Soniox
waits before ending a turn; unset keeps Soniox's default. Select `stt-rt-v6`
as the model for Korean.

With an AssemblyAI Universal-3 Pro backup (see
[Speech recognition (STT) fallback](./stt-fallback)), the backup ends turns
itself when it takes over.
