---
title: Voice (TTS) fallback
description: Optional backup voice when the primary TTS fails during a call.
---

Use `tts_fallback` to configure one optional backup voice for pipeline calls. A policy supports at most one `error` rule.

## JSON shape

```json
{
  "tts_fallback": {
    "version": 1,
    "rules": [
      {
        "condition": { "type": "error" },
        "target": {
          "provider_connection_uuid": "<uuid>",
          "settings": { "model": "...", "voice": "..." }
        }
      }
    ]
  }
}
```

Set it on named model configurations and workflow or API-trigger overrides. For pre-call overrides, see [Pre-Call Data Fetch](../voice-agent/pre-call-data-fetch). Resolved runs store the policy without credentials in the workflow snapshot.

## Runtime behavior

- The policy is off when omitted or when `rules` is empty. It is ignored in realtime mode. For pipeline calls, a Dograh-managed primary TTS or target is rejected with a 422.
- For pipeline calls, the backup must use a different provider connection or different TTS settings from the primary.
- A named model configuration without a voice fallback never stores or returns the `tts_fallback` key.
- An empty `rules` array disables an inherited policy. An override that sets `mode` describes a whole configuration and does not inherit one: it has no voice fallback unless it sets its own, so leave the key out to have none.
- Call metrics record `tts_fallback_metrics`: `switched` increments on each visit that successfully moved to the backup; `backup_unavailable` increments at most once per visit, when the inactive backup reports any error before it is used or its background connect raises. The count alone does not retire the backup: it stops being used only after a permanent error (authentication, authorization or an invalid request) or a connect that raises, and a later primary error then does not switch. After a transient error such as a 5xx the backup stays usable, and a later primary error still switches to it. A connect that only times out (3 seconds) is not counted: the backup stays eligible and reconnects when it first has to speak.
- When the backup is usable, the **first** primary error switches the voice for the rest of the visit. Dograh replays the text associated with the failed TTS request, including greetings and ordinary LLM responses, if the primary generated less than 3 seconds of audio for that request; after 3 seconds, it is not replayed. A transient error the primary could have recovered from also switches the voice (v1 behavior).

Configure through the API today; the Models UI editor ships in a follow-up change.
